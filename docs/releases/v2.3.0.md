# v2.3.0 release preparation — Roadmap 3

Proposed release title **PaperTrail v2.3.0 — Reader improvements, diagnostics and reliability**.
The last published stable version is v2.2.0. The proposed minor release includes reader fixes and enhancements, opt-in
diagnostics, and the PDF/EPUB performance work since that release. Version,
date and source SHA are pending owner review. [Roadmap 3 #107](https://github.com/HimanshuHD/papertrail-reader/issues/107)
coordinates release closeout.

## Owner release checklist

- [ ] Review the final #16 PR and explicitly accept the fixture target values,
      applicability and remaining measurement limitations. Record the actual
      browser evidence and accepted scope in #16.
- [ ] Merge the final #16 PR to staging. Verify the matching source checks and
      integration. Complete manual UI review of the release candidate, including
      PDF/EPUB open, saved positions, highlights, zoom, tabs and split view.
      Check formatted EPUBs with fonts and illustrations, mode restoration,
      internal/external links and keyboard focus, compact notices, and narrow
      PDF spreads/panning. Check opt-in diagnostics on a diagnostics-enabled
      build. Visual QA is independently dispatched by the owner when needed.
- [ ] Create a reviewed `release/2.3.0` PR to main from accepted staging.
      Update `package.json.version`, both lockfile version fields and
      `CHANGELOG.md`. Refresh the inventory against the exact accepted candidate
      and finalize the title, version and release notes in that PR. Before
      publishing the notes, remove draft wording and use exact-tag links for
      repository documents in the GitHub Release body.
- [ ] Verify main Candidate validation, production-path Browser E2E, live build
      identity, critical assets and acknowledged publication for the exact merge.
- [ ] Create `v2.3.0` at the reviewed main commit. Verify the exact-tag package
      run, dual-build manifests and package SHA-256. Review and publish its
      GitHub Release draft.
- [ ] Archive the released package through **Publish website** and verify the
      immutable URL, its identity/assets and isolated saved data. Use explicit
      promotion if the owner chooses to install the released package at the root.
- [ ] Synchronize main release fixes and version changes back to staging.
      Record delivery references and owner sign-off. Close #16 and milestone 9
      when their scope is accepted, then publish the final Wiki reconciliation
      and close Roadmap 3 (#107).

The release commit should add this changelog entry after version approval:

> **2.3.0 — Reader improvements, diagnostics and reliability.** Restores PDF
> and EPUB hyperlink handling, improves EPUB typography and illustration
> compatibility, and adds compact reader notices. Large documents benefit from
> PDF page virtualization and reduced EPUB preparation and scroll work. Opt-in
> developer diagnostics and scoped workload evidence support acceptance.
