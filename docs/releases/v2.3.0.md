## Manual UI review reference

Open [staging](https://himanshuhd.github.io/papertrail-reader/staging/#/app)
after its publication receipt is acknowledged. Compare the footer/build ID
with the receipt's saved candidate SHA and run, then confirm that the receipt
names staging source `d54bc70` and its tree. The build SHA may be a saved PR
candidate rather than the merge SHA; the version stays 2.2.0 until release
metadata is bumped. Record pass/fail/unavailable by case. Use generated or
disposable local documents and share only reviewed outcomes.

| Area              | Review steps and expected behavior                                                                                                                                                                                                                                                                                                    |
| ----------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Library and state | Open a nested local library and PDF/EPUB tabs. Cancel a picker; current reading continues. Reload and reselect matching content; order, page/chapter, zoom and EPUB mode restore. This smoke check does not certify real permission revocation (#274).                                                                                |
| PDF               | Open a long text PDF and an image-heavy PDF. Scroll, jump pages, resize, change zoom/fit and toggle spreads. At narrow width pan an oversized page to both edges. Check search excerpts, saved highlights and bookmark/position continuity.                                                                                           |
| EPUB              | Open a long styled chapter, SVG/cover and supported embedded-font examples. Navigate chapters, resize and toggle text-only. Confirm the visible passage stays anchored, notices leave reading space intact, and unsupported resources fall back with readable text.                                                                   |
| Links             | Follow PDF named/explicit destinations and EPUB chapter/footnote/return links. External mouse, Enter, modifier and middle-click activation must require one confirmation; Cancel/Escape opens nothing and restores focus; confirmation opens one isolated tab.                                                                        |
| Workspace         | Switch warm tabs, use Split view, focus each pane, swap and exit. Check independent navigation/zoom/annotations and close/reopen restoration. Verify empty annotation export is disabled.                                                                                                                                             |
| Diagnostics       | On diagnostics-enabled staging, inspect Overview, Operations, Timeline, Sensors, Resources and Technical details. Check keyboard tabs/focus, narrow layouts, minimize/restore, pause/resume and local export without document text. Unavailable sensors should say unavailable. Ordinary production omits instrumentation by default. |
| Visual review     | If requested, dispatch Visual QA manually against the exact candidate. Review screenshots and report; no automatic baseline adoption or delivery gate.                                                                                                                                                                                |

The owner accepted `roadmap-3-fixture-targets-v1` on 10 November 2026.
This decision is separate from manual UI review. The three target pairs are 475/950 ms for library scan,
425/850 ms for PDF cold open and 400/800 ms for EPUB cold open. They are limited
to the generated fixtures and calibrated configuration in the
[target review](../development/performance-target-review.md), including the
discovery-service versus visible busy-hold distinction. Real exports exercise
the operation boundary; unit sequences exercise sustained breach and recovery.
Do not extrapolate to all browsers/documents, a total-memory/leak verdict,
physical GPU, native/worker heap or unattributed historical spikes.

## Packaging and live verification

1. After the owner merges and the main delivery is verified, resolve the
   reviewed merge SHA and tree. Only the owner creates and pushes
   `v2.3.0` at that exact commit. Check all package/lock versions equal 2.3.0.
2. Verify **Package versioned release** for the exact tag. Download
   `papertrail-v2.3.0.json` and its `.sha256`; compare the digest with
   `Get-FileHash -Algorithm SHA256 papertrail-v2.3.0.json` or
   `sha256sum -c papertrail-v2.3.0.json.sha256`. Verify both embedded build
   manifests and payloads with the repository release-package verifier.
   Require matching tag, commit, tree, run and version, and distinct root and
   `/papertrail-reader/releases/v2.3.0/` base paths. Review the generated
   draft release body and publish only with owner authorization.
3. In **Publish website** on main, select `archive-release` with
   `release_tag: v2.3.0`. Verify the immutable URL's `build.json`, app
   startup and critical assets against the package. With a disposable PDF/EPUB,
   verify that bookmarks and reading positions remain isolated from the root.
   Check the acknowledged receipt and preservation of staging/other versions.
4. If the owner explicitly requests `promote-release`, verify the root's
   identity/assets and its existing reading state against the package and
   receipt. Keep the immutable URL intact. Use the versioned guide for
   recovery; never retag or replace published assets.
5. Back-sync the reviewed main version/notes changes to staging. Record the
   exact release PR, main merge, tag, package run/hash, immutable URL and
   delivery receipts in #107. Reconcile #16/milestone 9/roadmap closure only
   after the recorded acceptance and verified delivery. Keep #274/#275/#278
   separate.
